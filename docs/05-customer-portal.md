# 05 — Customer Portal

Two entry personas: practice/client and ROOT employee. Sign-in methods planned: email, Google, Microsoft only after Appwrite OAuth providers configured. Organizations, memberships, staff permissions and cross-tenant data are enforced server-side.

Module map: account/profile, dashboard, subscriptions, onboarding, service requests, A/R and denial work queues, prior authorization, eligibility, charges, payments, credentialing, contracts, practice operations, reports, notifications, documents, integrations, employee queue, roles and team settings.

Use fictional organizations in demos. Tier-gating is advisory in UI; server security decisions are authoritative. All screens need loading, empty, success, error, permission-denied and retry states.
